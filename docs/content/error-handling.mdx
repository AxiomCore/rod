Rod provides a detailed and structured approach to error handling, designed to give you maximum insight into validation failures.

## The `RodResult`

Every validation call returns a `RodResult<RodValue>`, which is a standard Rust `Result`.

-   `Ok(RodValue)`: The validation was successful. The `RodValue` is a zero-copy enum containing the validated data.
-   `Err(RodError)`: The validation failed. The `RodError` contains detailed information about all failures.

```rust
use rod::{string, RodValidator};
use rod::io::json::wrap;
use serde_json::json;

let schema = string();
let result = schema.validate(&wrap(&json!("hello")));

match result {
    Ok(rod_value) => {
        // Safely work with the validated string
        println!("Valid string: {}", rod_value.as_str().unwrap());
    }
    Err(error) => {
        // Handle the validation error
        eprintln!("Validation failed!");
    }
}
```

## The `RodError` Struct

When validation fails, you get a `RodError`. Its most important field is `issues`, which is a `Vec<RodIssue>`. Rod is designed to report all validation errors at once, not just the first one it finds.

```rust
pub struct RodError {
    pub issues: Vec<RodIssue>,
}
```

## The `RodIssue` Struct

Each `RodIssue` represents a single validation failure. It contains a structured breakdown of the error.

-   `path: Vec<String>`: The path to the invalid field (e.g., `["user", "email"]`).
-   `message: String`: A human-readable error message.
-   `details: RodIssueCode`: A machine-readable enum detailing the specific error type.

### Example: Inspecting Issues

```rust
use rod::{rod_obj, string, number, RodValidator};
use rod::io::json::wrap;
use serde_json::json;

let schema = rod_obj! {
    username: string().min(3),
    age: number().int()
};

let invalid_data = json!({ "username": "a", "age": 18.5 });
let error = schema.validate(&wrap(&invalid_data)).unwrap_err();

assert_eq!(error.issues.len(), 2);

for issue in error.issues {
    println!(
        "Error at path '{:?}': {} (Code: {:?})",
        issue.path, issue.message, issue.details
    );
}

// Output would be similar to:
// Error at path '["username"]': String must contain at least 3 character(s) (Code: TooSmall { ... })
// Error at path '["age"]': Expected integer, received float (Code: InvalidType { ... })
```

By inspecting the `details` field (`RodIssueCode`), you can programmatically handle specific types of errors, such as "too small," "invalid type," or "unrecognized keys."
