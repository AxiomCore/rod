# Introduction

**Rod** is a high-performance, cross-platform schema validation library powered by Rust. It allows you to define validation logic once and run it consistently across your entire stack: **Rust** backends, **JavaScript/TypeScript** frontends (via WASM), and **Python** data pipelines (via PyO3).

## The Problem: Schema Drift

In modern full-stack development, validation logic is often duplicated:
1.  **Backend (Rust/Go):** Enforces data integrity before saving to DB.
2.  **Frontend (TypeScript):** Provides immediate feedback to users (e.g., Zod).
3.  **Data/ML (Python):** Cleans datasets (e.g., Pydantic).

Keeping these three layers in sync is manual, error-prone, and leads to "Schema Drift"—where the frontend thinks an email is valid, but the backend rejects it.

## The Rod Solution

Rod moves the validation logic into a shared **Rust Core**. This core is compiled into native binaries, WebAssembly, and Python extensions.

- **Consistent:** A `uuid()` check in the browser uses the exact same byte-level logic as the backend.
- **Portable:** Share schemas via YAML specifications or builder patterns.
- **Zero-Copy Architecture:** Rod attempts to validate data in-place without serializing it to an intermediate format first.

## Performance Reality Check

Rod prioritizes **consistency** and **portability**. While the Rust core is incredibly fast (nanosecond-scale), calling Rod from JavaScript or Python involves a "Bridge Tax"—the overhead of crossing the Foreign Function Interface (FFI).

| Environment | Best Use Case | Performance Profile |
| :--- | :--- | :--- |
| **Native Rust** | High-performance backends | **🚀 Ultra Fast** (Comparable to handwritten checks) |
| **JavaScript** | Consistency-critical apps, Batch processing | **⚠️ Moderate** (Slower than Zod for small objects due to FFI overhead) |
| **Python** | Shared logic with backend | **⚠️ Moderate** (Slower than Pydantic for simple iteration) |

<Callout type="warn" title="When NOT to use Rod">
If your <strong>only</strong> goal is raw speed for validating small, simple objects in the browser (e.g., a simple login form), libraries like <strong>Zod</strong> will be faster because they run directly inside the JavaScript V8 engine without the overhead of WASM communication.

Choose Rod when you need <strong>guaranteed consistency</strong> across languages or need to validate <strong>massive datasets</strong> efficiently.
</Callout>

## Key Features

- **Zod-like API:** Fluent builder pattern (`rod.string().min(5)`) familiar to TypeScript developers.
- **Cross-Platform:** Works in Node.js, Browsers, Rust, and Python.
- **Rich Primitives:** Built-in support for UUIDs, CUIDs, IP addresses, URLs, and Datetimes.
- **Batch Optimization:** Specialized methods to validate arrays of primitives via bitmasks, bypassing per-item bridge costs.
