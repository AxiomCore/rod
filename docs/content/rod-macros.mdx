# Procedural Macros

Rod allows you to automatically generate validation schemas directly from your Rust structs using the `#[derive(Rod)]` macro. This enables a **Schema-Driven Development** workflow similar to `serde`.

<Callout type="info">
This feature requires the `macros` feature flag, which is enabled by default.
</Callout>

## Basic Usage

Simply derive `Rod` on your struct and use the `#[rod(...)]` attribute to define validation rules.

```rust
use rod_rs::{Rod, RodSchema};

#[derive(Rod, Debug)]
struct User {
    #[rod(min = 3, max = 20)]
    username: String,

    #[rod(email)]
    email: String,

    #[rod(min = 18)]
    age: u8,

    is_active: bool,
}

fn main() {
    // Generate the schema automatically
    let schema = User::schema();

    // Validate JSON data
    let data = serde_json::json!({
        "username": "Rod",
        "email": "hello@rod.rs",
        "age": 25,
        "is_active": true
    });

    let result = schema.validate(&rod_rs::io::json::wrap(&data));
    assert!(result.is_ok());
}
```

## Supported Attributes

These attributes map directly to Rod's builder API.

| Attribute | Type | Description |
| :--- | :--- | :--- |
| `#[rod(min = N)]` | Number/String | Minimum value or length. |
| `#[rod(max = N)]` | Number/String | Maximum value or length. |
| `#[rod(email)]` | String | Validates email format. |
| `#[rod(url)]` | String | Validates URL format. |
| `#[rod(uuid)]` | String | Validates UUID v4. |
| `#[rod(cuid)]` | String | Validates CUID format. |
| `#[rod(regex = "...")]` | String | Validates against a Regex pattern. |

## Supported Types & Heuristics

The macro uses **heuristic path matching** to identify types. This means it looks at the type name (e.g., "Vec", "Option") rather than resolving the full type system.

### 1. Primitives
| Rust Type | Rod Schema |
| :--- | :--- |
| `String`, `&str`, `Cow<str>` | `rod::string()` |
| `bool` | `rod::boolean()` |
| `f32`, `f64` | `rod::number()` |
| `i32`, `u32`, `usize`, etc. | `rod::number().int()` |
| `char` | `rod::string()` |

### 2. Containers
| Rust Type | Rod Schema | Notes |
| :--- | :--- | :--- |
| `Option<T>` | `T.nullable().optional()` | Handles both `null` and missing keys. |
| `Vec<T>` | `rod::array(T)` | Also supports `VecDeque`, `LinkedList`. |
| `HashSet<T>` | `rod::set(T)` | Also supports `BTreeSet`. |
| `HashMap<K, V>` | `rod::record(K, V)` | Also supports `BTreeMap`. |
| `[T; N]` | `rod::array(T)` | Ignores fixed length `N` currently. |

### 3. Smart Pointers & References
The macro automatically "peels" these wrappers to validate the inner value:
- `Box<T>`
- `Rc<T>`, `Arc<T>`
- `Cell<T>`, `RefCell<T>`
- `Mutex<T>`, `RwLock<T>`
- `&T` (References)

### 4. Date & Time
Requires the `chrono` crate types.
- `chrono::DateTime<Utc>`
- `chrono::NaiveDate`
- `std::time::SystemTime`
- **Result:** `rod::date()` (Expects Unix timestamp integer/float).

### 5. Nested Structs & Generics
You can nest structs seamlessly. The inner struct must also implement `RodSchema`.

```rust
#[derive(Rod)]
struct Address {
    city: String
}

#[derive(Rod)]
struct User<T> {
    profile: T,        // Generic T must implement RodSchema
    address: Address,  // Nested Struct
}
```

<Callout type="warn" title="Heuristic Limitations">
Because the macro matches on type names (e.g., `Vec`), it may fail if you alias standard types (e.g., `type MyList = Vec<String>`). Use standard type names for best compatibility.
</Callout>
