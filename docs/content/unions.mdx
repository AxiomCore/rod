# Unions

Unions allow a field to match one of several schemas. Rod provides two types of unions: Standard Unions and Discriminated Unions.

## Standard Unions (`rod.union`)

Rod attempts to validate the input against each schema in the list, **in order**. The first one that succeeds is returned.

```typescript
const StringOrNumber = rod.union(
    rod.string(), 
    rod.number()
);

StringOrNumber.parse("hello"); // ✅ String
StringOrNumber.parse(42);      // ✅ Number
StringOrNumber.parse(true);    // ❌ Error
```

<Callout type="warn">
**Performance Warning:** Standard unions are $O(N)$ operations. If you have a union of 10 complex objects, Rod might have to run full validation 10 times to find a match (or fail). For complex data structures, this is slow.
</Callout>

## Discriminated Unions (`rod.discriminatedUnion`)

This is the **optimized** way to handle polymorphic data. If your objects share a common field (like `type`, `kind`, or `status`), Rod can pick the correct validator immediately ($O(1)$) without checking the others.

**This is highly recommended for performance.**

```typescript
const Circle = rod.object({
  kind: rod.literal("circle"),
  radius: rod.number()
});

const Square = rod.object({
  kind: rod.literal("square"),
  side: rod.number()
});

// "kind" is the discriminator key
const Shape = rod.discriminatedUnion("kind", [
  Circle,
  Square
]);

// 🚀 Rod instantly knows to use the Square validator
Shape.parse({ kind: "square", side: 10 });
```

### Why use Discriminated Unions?

Imagine a union of 50 different event types.
- **Standard Union:** Rod tries Schema 1, fails... Schema 2, fails... Schema 49, success. (Slow)
- **Discriminated Union:** Rod looks at `event.type`, sees `"login_success"`, and jumps directly to Schema 49. (Fast)

```typescript
// Example: Redux/Event Sourcing Actions
const Action = rod.discriminatedUnion("type", [
  rod.object({ type: rod.literal("LOGIN"), payload: UserSchema }),
  rod.object({ type: rod.literal("LOGOUT") }),
  // ... 50 more
]);
```
